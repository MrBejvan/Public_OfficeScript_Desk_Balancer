# Desk Coverage Scheduler

Automates a real staffing problem from a hospital unit: turning a Kronos
schedule export into a fair, balanced daily assignment across four service
desks (**East, West, VAB, Resource**) — a task a scheduling manager was
previously doing by hand every period.

The same scheduling rules are implemented twice, for two different
deployment realities:

| | [`desk-scheduler/`](desk-scheduler/) | [`office-script/`](office-script/) |
|---|---|---|
| **Language** | Python 3 + Tkinter | TypeScript (Office Scripts) |
| **Runs as** | Offline desktop app | Script inside Excel (Microsoft 365), optionally triggered by Power Automate |
| **Why** | Fully local, zero network code — the strictest data-handling option | Locked-down hospital machines block unsigned executables; Office Scripts runs inside infrastructure IT already governs |
| **Tests** | pytest suite (importer, scheduler, exporter) | Node built-in test runner, mirroring the scheduling logic outside the Excel runtime |

## Why two versions

I built the Python app first: a modular, fully tested desktop tool with no
network access at all. Then I hit the actual constraint — a standard-user
hospital Windows image won't run an arbitrary executable, and often blocks
the command line entirely. Rather than ask IT to approve new software, I
ported the logic to Office Scripts, which runs inside Excel with no install
and no admin rights. The tradeoff (data now lives in OneDrive/SharePoint
instead of a purely local file) is documented in that version's README.

The Office Scripts version has since moved ahead: it adds an employee
roster with weekly shift caps (Full Time / Part Time / Flex / 3-2) and a
randomized desk rotation so everyone cycles through all four desks.

## What both versions do

1. **Import** Kronos's real "Location Schedule - Monthly" export — a wide,
   merged-cell grid, not a clean table — including shift codes, PTO, and
   "please don't schedule me" markers.
2. **Fill desks in priority order** (East and West first), leaving any desk
   that can't be covered blank and flagged rather than guessing.
3. **Balance fairly** so coverage doesn't fall on the same people every time.
4. **Export** a printable monthly calendar plus Summary and Needs Attention
   sheets.

Input is validated defensively throughout: names and dates are checked
before use, bad rows are skipped and reported individually, and formula
or macro content is never trusted.

## Quick start

**Python version**
```bash
cd desk-scheduler
pip install -r requirements.txt
python main.py        # click "Use Sample Data" to try it
pytest -v             # run the tests
```

**Office Scripts version** — see [`office-script/README.md`](office-script/README.md)
for setup in Excel. To run the logic tests locally:
```bash
cd office-script
node --test tests/scheduler-logic.test.mjs
```

## About the sample data

All names, schedules, and location codes in this repository are synthetic.
The sample files are generated by `desk-scheduler/sample_data/generate_sample.py`
and `office-script/sample_data/generate_template.py`, shaped to match a real
export's layout without containing any real employee data.
